# 样本数据

这里放的是**真实卡片**的完整分析记录，用于对照学习 MIFARE Classic 卡的数据结构与扣费逻辑。

## water-card-A1B2C3D4/

一张校园水卡的完整分析（MIFARE Classic 1K 兼容卡）：

| 文件 | 内容 |
|---|---|
| `CARD-REPORT.md` | 技术分析报告：卡型判断、密钥表、字段布局、校验算法、滚动码结论 |
| `dump_before_197.34.mfd` / `.txt` | 消费前 dump（余额 197.34 元） |
| `dump_after_195.43.mfd` / `.txt` | 消费后 dump（余额 195.43 元） |
| `KEY-BLOCK-DIFF.txt` | 一次消费（1.91 元）引起的变化块 |
| `keys_full.mfd` | 16 扇区完整密钥（nfc-mfclassic 格式） |
| `keys.dic` | 密钥字典 |

**可以学到什么**

- 存款型 M1 卡的典型布局：余额（小端 16 位，单位 0.01 元）+ 次数计数器 + 单字节 XOR 校验
- 双副本同步（扇区 02/03 的块 0 内容完全一致，扣费时同步重写）
- 弱校验的实际形态：`末字节 = 前 15 字节异或`，可自行验算
- 为什么"块 0 不可写"会让手机虚拟卡无法 bit-perfect 复刻

## ⚠️ 关于这些数据的风险提示

这些文件包含一张**仍在使用的真实卡片**的完整密钥与余额数据。

- 任何人都能据此制作该卡的克隆体
- 若该系统有后台余额对账，克隆卡与原卡混用可能触发异常

如果你要引用这些数据写文章，建议**只引用结构和算法，打码具体密钥与 UID**：

```
UID: A1B2C3D4        →  AA★BB★CC★
KeyA: F3DD1B9B0343   →  ★★★★★★★★★★
```

删除本样本：

```bash
git rm -r samples/water-card-A1B2C3D4
git commit -m "remove sample data"
git push
```

> 注意：Git 历史里仍会保留旧提交，彻底清除需要改写历史（`git filter-repo`）或删除整个仓库重建。
